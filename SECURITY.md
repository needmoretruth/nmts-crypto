# Reporting a security problem

**Report it privately first.** Not as a public issue, and not on social media.

Two ways in, both fine:

- **Email** — **nmts@nmts.me**. Reaches the operator directly.
- **The form at https://nmts.me/ask** — needs no account and no email address of yours. It hands
  you a reference number and a reading code; come back with those to read the answer.
  ⚠ Messages left in the form are deleted after 30 days, so use email for a long thread.

The whole policy, including what happens after a report arrives, is at **https://nmts.me/security**,
and the machine-readable version is at `https://nmts.me/.well-known/security.txt`.

## What to put in it

What you did, what happened, and how it can be seen again from here. If it needs a file or a
screenshot, say so and you will be told where to put it — the form takes text only.

## What NMTS holds, and what it cannot

Files are encrypted in the browser, so the operator cannot decrypt file contents. The server does
see file counts, sizes and times. That is worth knowing before you write, because it changes what
a finding means.

## Scope

This repository is one part of NMTS. A fault in the running service, in the browser app, or in the
server belongs at the same two addresses — send it there rather than opening an issue here.

## What is not promised

No bounty, no payment, and no fixed reply time. Reports are read.
